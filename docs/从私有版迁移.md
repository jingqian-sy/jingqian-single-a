# 从私有版迁移到开源版（2026-11-02 实际操作记录）

> 背景：私有版（`<你的私有版目录>`，1.6.0）退休，以后只用开源版（软件窗口 + 内置 MCP 适配）。
> 这篇写清楚「搬了什么、搬到哪、怎么回退」，以后出问题照这个查。

## 一、搬了什么

| 东西 | 从哪 | 到哪 |
| --- | --- | --- |
| 长期记忆（819 条） | `<你的私有版目录>\memory-service\memory.db` | 开源版 `data/memory/memories.json`（安装版在 `%LOCALAPPDATA%\Jingqian\app\data\memory\`） |
| 记忆（导出快照 782 条） | `<你的私有版目录>\state\memories-export.json` | 同上，按文字去重合并（和 db 重复的不重复导） |

## 二、记忆服务搬出私有目录

私有版的「统一记忆服务」（18700）原来跑在 `<你的私有版目录>\memory-service`，QQ 桥接和 DSH 的 `memory` MCP 都靠它。
现在整目录复制到：

```
C:\Users\你的用户名\Documents\deepseek-harness\default-workspace\memory-service
```

- QQ 桥接的 `bridge.js` / `link-guard.js` 本来就指向这个路径（`MEMORY_DIR`），所以它们会自动从这里拉起 18700；
- DSH 配置（`~/.dsh/profiles/desktop/cordis.patch.yml`）里的 `mcp-memory-service` 已改到新路径；
- DSH 的 `jingqian` MCP 从私有版包装（`mcp-jingqian\server.mjs`，走 7888）换成开源版 `src/mcp/server.js`（走 7889，四个工具：ask / memory_remember / memory_search / stats）。

## 三、私有版的「作废」怎么做

1. 开机自启只留：`鲸倩任务队列`、`鲸倩看护`（her-loop，还在用）、`WhaleLinkGuard`（QQ 桥接看护）；
   删掉：`鲸倩独立服务`（7888）、`鲸倩独立看护`、`鲸倩记忆服务`（老路径；18700 现在由 link-guard/桥接拉）。
2. `<你的私有版目录>` 先改名 `<你的私有版目录>-停用`，观察一周没异常再删。
3. 备份：`<你的备份目录>\迁移` 里有私有 core 的 state/memory-service/config 快照、DSH 配置、开源版 data。

## 四、回退

- 记忆：把 `data/memory/memories.json` 换回迁移前的备份（`<你的备份目录>\迁移\open-data\memory\memories.json`）。
- 配置：`<你的备份目录>\迁移\core\core-config.json` 是私有版原配置；开源版配置改坏了可以从备份目录找。
- DSH：`cordis.patch.yml` 的备份在同目录 `cordis.patch.yml.bak-migrate-*`。
- 私有版：把 `<你的私有版目录>-停用` 改回原名，恢复那三个自启快捷方式，就能回 7888 那套。

## 五、迁移脚本

记忆迁移脚本在 `tools/migrate-private-memory.py`（只读私有库、写开源 data，可重复跑；按文字去重，不会重复导入）。
