# 设计决定：两个模板（单A / 3A）

结论先行：**共用协议，不共用实现；评测各一套；数据互不串。** 这不是为了省事，是为了可比较、可维护。

## 一、共用的（只做协议，不做实现）

只定格式和约定，两边各自实现，互不 import：

| 协议 | 内容 |
|---|---|
| 记忆条目 | id / text / kind / importance / pinned / created_at / updated_at / status |
| 事件层 | event_id / 标题 / 时间段 / 参与实体 / 关联记忆 id / 结果 |
| 图谱 | 三元组：主体 / 关系 / 客体，附来源记忆 id 与置信度 |
| 工具契约 | name / 入参 schema / 返回结构 / 红线级别 / 是否可逆 |
| 消息信封 | 谁发 / 给谁 / 任务号 / 状态 / 载荷 schema / 时间 / 依赖 |
| 账本 | 按天按模型：tokens / 调用次数 / 估算花费 / 免费额度剩余 |
| 红线 | P0 直接拒 / P1-P2 需确认 / P3 放行；每条落审计 |
| 评测集 | 同一批任务定义（输入、判定标准、权重），两边都跑 |

## 二、各自写的（不共用代码路径）

| | 单A 模板 | 3A 模板 |
|---|---|---|
| 编排 | 主脑单线程循环 | 调度 → 执行 → 质检，带打回 |
| 状态机 | 单任务串行：待批准→排队→执行→汇总 | 父任务 + 子任务依赖图，单写者=调度 |
| 提示词 | 一份主脑人格 | 三个角色各一份，禁止串戏 |
| 打回 | 无 | 质检可打回，最多 2 轮，超了升级给人 |
| 数据目录 | 独立 | 独立（另一套库、另一套账本） |
| 评测 | 自己的基准 | 自己的基准（任务集相同，独立跑） |

## 三、稳定性清单（两个模板都必须做到）

1. 每步落盘，断点可续；崩溃后启动时把「执行中」判失败并可重跑。
2. 状态单写者：任何时刻只有一个进程能改任务状态。
3. 超时三档分开：预处理 / 执行 / 汇总；熔断后走降级，不死等。
4. 重试有上限（默认 1 次），带退避；超过就升级给人。
5. 跨进程消息强制 schema 校验，不合格直接拒收并记日志。
6. 幂等：同一任务号重放不产生第二份副作用。
7. 启动自检 + 每周还原演练（单A 已有，3A 照抄机制）。
8. 改动前先跑 Evals，跑不过不上。
9. 所有动作留审计，可按级别和放行情况筛。

## 四、效率清单

1. 工具渐进披露：按任务阶段分批给工具，别一次性塞满（前缀短 → 缓存命中高）。
2. 缓存友好前缀：人设固定在最前，每轮变化的内容放后面。
3. Plan-Execute：先出计划再动手，减少无效工具轮次。
4. 本地小模型包掉预处理、摘要、质检；云端只出判断。
5. 并行只用在互不相干的读操作上；有写冲突的一律串行。
6. 预算护栏：单任务 token / 时间上限，超了降级或停，不是无限烧。
7. 度量报表：每任务成本、耗时、失败率、返工次数、缓存命中率。

## 五、不做的

- 视频理解。
- 多 Agent 常驻编排放进主线（只作为演示模板）。

## 五之二、沙盒：做成开关，默认关

沙盒是**可配置项**，不是非黑即白：

```json
{ "sandbox": { "mode": "none" } }
```

| mode | 行为 | 适用 |
|---|---|---|
| `none`（默认） | 直接执行，只靠红线 + 白名单 + 受限目录 | 自己的电脑、自己用（我们现在就这个） |
| `process` | 子进程 + 临时工作目录 + 超时 + 资源上限 | 半可信场景 |
| `docker` | 容器内执行，代码与宿主隔离 | 跑别人的代码、多租户 |

要求：
- 默认 `none`，不许默认开 docker（很多人没装 WSL2，一开就跑不起来）。
- 切到 `docker` 时，检测不到环境要**明确报错并回退**到 `process`，不能静默失败。
- README 里如实写：沙盒是可选项，默认不开；开了会慢、有额外依赖。
- 我们本机（老爸这台）保持 `none`。

## 六、验收标准（两个模板都要过）

- 同一批 10 个真实任务：两边都跑一遍，报表能对比。
- 单A：连续跑 3 天不出错，重启能续。
- 3A：调度进程单独重启后，任务不丢、状态可恢复。
- 两个模板都能一条命令起来，都不含私人数据。
