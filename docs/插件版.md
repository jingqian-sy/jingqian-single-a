# 插件版（MCP）：一行配置挂到你的客户端

> 对外只有两个形态：**软件版**（C# 窗口，主）和**插件版**（MCP，次）。
> 插件版不重复实现业务：所有调用转发给本机 Node 服务，聊天/记忆/工具/红线都在服务里。

## 一、挂一行配置

把下面这段加到你客户端（DSH / Cherry Studio 等支持 MCP 的）配置里，把路径换成你的仓库绝对路径：

```json
{
  "mcpServers": {
    "jingqian": {
      "command": "node",
      "args": ["D:\\鲸倩开源-雏版\\src\\mcp\\server.js"]
    }
  }
}
```

- 客户端里会多出 4 个工具：`ask`、`memory_search`、`memory_remember`、`stats`。
- 服务地址默认 `http://127.0.0.1:7889`；换端口用环境变量 `JINGQIAN_URL`。
- 服务没起时插件会自己拉一次（`node src/server.js`），和软件版同一套逻辑。
- 客户端要能跑 `node`（PATH 里有，或把 command 换成 node 的绝对路径）。

## 二、这 4 个工具

| 工具 | 干什么 | 背后接口 |
|---|---|---|
| `ask` | 跟鲸倩说一句话，返回她原话（带记忆和工具） | `POST /api/chat` |
| `memory_search` | 搜记忆 | `GET /api/memory?query=` |
| `memory_remember` | 写一条记忆（可 pinned） | `POST /api/memory` |
| `stats` | 模型/今日调用/tokens/记忆条数 | `GET /api/stats` |

## 三、和另外两个入口的关系

```
            ┌─────────────┐
  DSH/Cherry│ 插件版 MCP   │──┐
  客户端     └─────────────┘  │
                             ├──▶ 本机 Node 服务（127.0.0.1:7889）──▶ 记忆/工具/模型
 普通用户    ┌─────────────┐  │
            │ 软件版 exe    │──┘
            └─────────────┘
 开发调试    ┌─────────────┐
            │ 网页版 :7889  │──┘
            └─────────────┘
```

三个入口，一套服务、一份记忆、一份账本。网页版是开发调试用的，不是给用户的功能形态。

## 四、注意

- 插件版同样没有鉴权，只适合本机客户端，别把 7889 暴露到公网。
- 记忆是同一个库：插件里记的事，软件版打开就能看到。
- 客户端超时设置要够（`ask` 可能走多步工具，默认 180 秒）。

## 五、怎么验（这轮真跑过的）

```cmd
node evals\mcp-test.js
```

这个用例不起眼但挺硬：它按 MCP 的 stdio 协议（一行一个 JSON-RPC）真的跟 `src/mcp/server.js` 聊一遍，
临时起一个服务 + 本地假模型，不碰真实记忆、不联网。14 条断言覆盖：

- `initialize` 回协议版本和 `serverInfo: jingqian-single-a`；
- `notifications/initialized` 不返回东西，但后面的请求照常；
- `tools/list` 正好四个工具（ask / memory_search / memory_remember / stats）；
- `memory_remember` 真写进库、`memory_search` 能搜回来、`stats` 条数对得上；
- `ask` 真的走 `/api/chat` 拿到回复（不是本地拼的假回复）；
- 不认识的方法回 `-32601`、不认识的工具回 `isError`，进程不崩、之后还能用。

这条已经进 CI（第 20 步），每次推代码都会跑。
