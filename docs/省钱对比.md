# 省钱对比：全云端 vs 本地 + 免费额度优先

> 一句话结论：同一批 55 道题、跑两遍（110 次调用、237,910 tokens），
> **本机 Ollama 实测花费 0 元**；同样的 tokens 如果全走云端，按 DeepSeek 高峰价约 **0.78 元**，
> 空闲时段约 **0.39 元**。省下来的不是百分比噱头，是「粗活根本不用花钱」这件事本身。

这份文件里的每个数字都能顺着文件名和 run_id 查回去，单价写清按哪家、哪天查的。

计算方式（以高峰档为例，数字来自 S3）：

```

输出  50,221 / 1e6 × 8 元 = 0.401768 元
合计                      = 0.777146 元
```

也就是说：**这一整轮 55 题 × 2 遍，跑在本地不到八毛钱（按云端价折算），实际一分没花。**

| 分组 | 调用次数 | 输入 tokens | 输出 tokens | 高峰折算（元） |
|---|---|---|---|---|

| 诚实 honesty | 16 | 21,496 | 6,171 | 0.092 |
| 风格 style | 16 | 17,667 | 5,368 | 0.078 |

> 折算列 = 输入/1e6×2 + 输出/1e6×8，四舍五入到 0.001 元；逐行相加与合计可能有 0.001 的尾差。

看得出来的两件事：

1. **大头在「多步」和「工具」**：一次任务反复调工具，输入 tokens 涨得最快——
   这正是「渐进披露工具 + 预算护栏 + 事件层少喂废话」要压的地方。
2. **粗活（记东西、读文件、跑命令）根本不需要大模型**。本地 8B 能做的就不上云端，
   省下的不是 10%，是整段。

## 五、它到底怎么省（不是靠一个便宜模型）

- **本地优先**：`route.mode: "cheap-first"`，本地/免费额度排在前面，云端是兜底。
- **难度判断**：话长、带「分析/架构/为什么/代码」这类词的，先上云端（`route.escalate`）——
  省归省，值钱的判断不省。
- **免费额度优先**：智谱 `glm-4-flash` 这类免费档填在 providers 里，价格按 0 记，先用完再换。
- **预算护栏**：单次调用 / 单轮 / 单任务都有秒数与 token 上限（`budget`），超了降级停下，
  不会「一个死循环烧掉一天额度」。
- **账本**：每次调用按天按 provider 记账（`data/ledger/`，样例见 S4），
  有数才谈得上优化。
- **失败回退**：一家挂了自动换下一家（`data/route.log`），不会卡死也不会重复烧钱。

## 六、什么情况下省不下来（如实写）

- **复杂任务仍要云端**：难度判断会把长任务推给云端，这部分钱省不掉，也不该省。
- **本地不是零成本**：电费、机器折旧没算进 0 元里；这轮是本机现成的 8B，没摊硬件钱。
- **8B 的便宜是用质量换的**：这轮 54/55，但慢（平均 21 秒/遍）；要更快更稳就得花钱。
- **免费额度有限速和上限**：免费档通常并发低、随时可能调整，不能当无限用。
- **tokens 是本地算的**：本地调用没有账单，tokens 由 Ollama 返回的 usage 统计，
  和云端计费口径可能有细微差异。

## 七、自己复算

```bash
node evals/ledger-summary.js     # 从 data/results.json 重新聚合，改写 data/ledger-summary.json
node evals/run.js --report       # 重写 data/report.md
```

换一台机器、换一家模型，跑一遍 `node evals/run.js --run --fresh` 就有你自己的数；
把 `data/ledger-summary.json` 里的 `equivalents` 换成你查到的单价，就是你的对比表。
