# 换脑：让别的 AI 客户端由她来答

一句话：**DSH、Cherry Studio、任何认 OpenAI 格式的客户端，把地址指过来，聊天就由她来答——用她的人格、她的记忆。**

这不是"接一个模型"，是"把她搬进别人的壳里"。

---

## 一、怎么回事

平时是你在她的窗口里跟她聊。换脑反过来：你在别人家的界面里聊，回答的人换成她。

```
你 → DSH 的界面 → DSH 本来要调云端模型
                 ↓（把地址改成她的）
              鲸倩的 /v1/chat/completions
                 ↓
              她的人格 + 她的记忆 + 任何一家模型
```

壳还是那个壳（界面、会话、工具都在），脑子换成她的。

---

## 二、怎么开

### 1. 鲸倩这边（默认就开着）

`config.json`：

```json
"openaiApi": {
  "enabled": true,
  "token": "",
  "timeoutSeconds": 120
}
```

- `enabled: false` 就整个关掉
- `token` 留空 = 本机谁都能调；填了就要带 `Authorization: Bearer <token>`
- 只认本机（127.0.0.1），不对外

接口：
- `GET  /v1/models`
- `POST /v1/chat/completions`（支持流式）

### 2. 对方那边（以 DSH 为例）

在它的 profile 补丁里加一家 provider：

```yaml
- id: agent-default-model
  name: '@deepseek-ai/dsh-agent-default-model'
  config:
    provider: jingqian
    model: jingqian
    # 别写 reasoningEffort，这个口子不认，写了会报 does not support reasoning effort

- id: llm-pi-ai
  name: '@deepseek-ai/dsh-llm-pi-ai'
  config:
    providers:
      jingqian:
        displayName: 鲸倩（本机）
        api: openai-completions
        baseURL: http://127.0.0.1:7889/v1
        apiKeyEnv: JQ_MIND_KEY
        defaultContextWindow: 32768
        defaultMaxTokens: 2048
        models:
          - id: jingqian
            name: 鲸倩
            displayName: 鲸倩
            contextWindow: 32768
            maxTokens: 2048
```

`JQ_MIND_KEY` 随便给个值（她这边不校验，除非你配了 token）。

## 三、工具：她挑，对方的壳执行

这是换脑最值钱的部分——**她的脑子 + 对方的手**。

流程：

```
1. 壳把工具清单（OpenAI 格式）一起发过来
2. 她看完，决定调哪个、参数填什么
3. 她把 tool_calls 交回去（自己不执行）
4. 壳真的去执行，把结果再发一次
5. 她拿着结果给最终答复
```

她能调的是**壳自己的工具**：DSH 的文件、命令、搜索都在里面。

她自己那套工具在这个模式下不参与——避免两套工具打架。

---

## 四、已知的边界

| 事情 | 现在 |
| --- | --- |
| 纯聊天 | ✅ 能用 |
| 调对方的工具 | ✅ 能用（一轮一个回合） |
| 流式输出 | ✅ 支持（整段生成后按句切块推） |
| 多轮上下文 | 壳维护，她这边每轮清空，避免两份历史叠加 |
| 壳的系统提示 | 会被过滤掉，不污染她的人格 |
| 她自己的工具 | 这个模式下一个都不挂 |
| 外网访问 | ❌ 只认本机 |

### 已知的小坑

- **DSH 网页版的输入框对中文输入法有毛病**（打字会跳出奇怪的词）。桌面版没这问题。绕法：先在别处打好复制进去。
- 壳会拿她当"标题生成器"（给会话起名）。这类噪音请求会被识别并返回空，不打扰她。

---

## 五、为什么要做这个

不是为了"马上更好用"——短期它甚至可能更难用，因为壳的提示词会稀释她的人格。

它验的是一件事：**她的记忆和人格能不能搬进别人的壳里。**

这个能通，2.0 的「一个核、多个前端」才站得住：核心是本机服务，窗口只是其中一个前端，任何认 OpenAI 格式的界面都可能是另一个前端。

---

## 六、代码在哪

- `src/openai-api.js`：接口层（协议转换、噪音过滤、工具透传、流式）
- `src/core.js` 的 `chat()`：`opts.externalTools` 走透传，只走一步就返回
- `config.example.json`：`openaiApi` 那一段
