# 一个核、两个前端

> 一句话：鲸倩只有一个脑子——本机服务；窗口和 DSH/QQ 都只是接过来的前端。
> 以前管这个适配器叫「插件版」，现在它就是**内置 MCP 适配**，跟软件一起发，不单独发布。

## 结构

```
软件窗口（C#）        ┐
DSH（MCP 适配）      ├──▶ 本机服务 127.0.0.1:7889 ──▶ 记忆 / 工具 / 模型 / 账本
QQ 桥接（可选）       ┘        （一个核：人格、红线、记忆都在这里）
```

- 服务挂了，前端都连不上；前端关掉，服务照常跑、记忆照常存。
- 窗口不依赖 DSH；DSH 也不需要装鲸倩的插件，配一行 MCP 就能用。

## 四个入口，各用各的模式

模式只有两个：

| 模式 | 干什么 | 用谁 |
|---|---|---|
| 对话 chat | 不挂工具，只聊天 | 谁都能用，免费模型也轮得上 |
| 工作 work | 挂全套工具，真去读写/跑命令 | 只让能动手的模型接 |

每个入口在 `config.json` 的 `modes` 里各存一份，互不影响：

```json
"modes": { "desktop": "chat", "qq": "work", "mcp": "work" }
```

- 窗口工具栏那个「对话 / 工作」只管 `desktop`。
- `qq`、`mcp` 默认工作模式——它们是来干活的，不该被窗口的闲聊模式拖住。
- 不写 `modes` 就沿用老的 `mode` 字段（兼容旧配置）。
- 热切换：`POST /api/mode { entry, mode }`，下一句就生效，不用重启。

## 怎么把 DSH 接过来

MCP 适配是一个 stdio 服务，路径固定 `src/mcp/server.js`，不重复实现业务，所有调用转发给本机服务。
DSH 的配置里加一段（把路径换成你的仓库绝对路径；`node` 建议写绝对路径）：

```yaml
- insert:
    - id: mcp-jingqian
      name: '@deepseek-ai/dsh-mcp-client'
      config:
        serverName: jingqian
        transport: stdio
        command: 'C:\...\node.exe'
        args: ['D:\jingqian\src\mcp\server.js']
        cwd: 'D:\jingqian'
        toolCallTimeoutMs: 300000
        failOnStartupError: false
```

挂上后多出四个工具：

| 工具 | 干什么 | 背后 |
|---|---|---|
| `ask` | 跟这台机器上的鲸倩说一句（工作模式，带记忆和工具） | `POST /api/chat`（entry=mcp） |
| `memory_search` | 搜本机记忆库 | `GET /api/memory?query=` |
| `memory_remember` | 写一条记忆 | `POST /api/memory` |
| `stats` | 模型 / 今日调用 / 记忆条数 | `GET /api/stats` |

- 服务没起时适配器会自己拉一次（用正在跑它的那个 node，不看 PATH）。
- 服务地址默认 `http://127.0.0.1:7889`，换端口用环境变量 `JINGQIAN_URL`。

## 边界

- 服务只监听本机、没有鉴权，**别把 7889 暴露到公网**。
- 软件版记忆库和 DSH 自己的记忆是两套，不合并；DSH 通过 MCP 调 `ask` 时用的是软件版这一份。
- QQ 群聊需要自备白名单群和桥接；作者没有真实群聊数据，群聊能力只用模拟环境验证过（见 `docs/接QQ.md`）。

## 怎么验

```cmd
node evals\mcp-test.js     :: 真按 MCP 协议聊一遍（四个工具、出错不崩）
node evals\mode-test.js    :: 对话/工作模式、按入口分模式、热切换
desktop\鲸倩.exe --verify  :: 软件窗口自检（历史、复制、工具调用、设置保存）
```

## 2.0 待办：QQ 一键连接自动读令牌

1.0 的「自动找 QQ 桥接」只在自己存过令牌时才能发现网关闭（网关默认要 accessToken，没令牌只会拿到 401），所以第一次用的人必须去网关设置里复制一次令牌手填——视频里得多教 30 秒。

2.0 改成：本机探测端口时先试已存令牌，失败就尝试读同机网关的配置——
- SnowLuma：`%USERPROFILE%\SnowLuma\config\onebot.json` 的 `accessToken`
- NapCat：`config\onebot11_*.json` 的 `token`
- 读不到再提示手填，并在界面上给出"去哪里复制"的一句话。

目标：新用户从装网关到连上，不用打开任何配置文件。
