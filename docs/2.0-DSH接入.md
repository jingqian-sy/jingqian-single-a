# 内置 MCP 适配：一行配置挂到你的客户端

> 这是「一个核、两个前端」里的第二个前端，跟软件一起发，不单独发布。
> 它不重复实现业务：聊天、记忆、工具、红线都在本机服务里，适配器只做转发。

## 一、挂一行配置

把下面这段加到你客户端（DSH / Cherry Studio 等支持 MCP 的）配置里，路径换成你的仓库绝对路径：

```json
{
  "mcpServers": {
    "jingqian": {
      "command": "node",
      "args": ["D:\\鲸倩开源-雏版\\src\\mcp\\server.js"]
    }
  }
}
```

- 客户端里会多出 4 个工具：`ask`、`memory_search`、`memory_remember`、`stats`。
- 服务地址默认 `http://127.0.0.1:7889`；换端口用环境变量 `JINGQIAN_URL`。
- 服务没起时适配器会自己拉一次（`node src/server.js`），用的是正在跑适配器的那个 node，不依赖 PATH。
- `command` 最好写 node 的绝对路径（`C:\Users\你\AppData\Local\Jingqian\runtime\node-v22.14.0-win-x64\node.exe`）。

## 二、这 4 个工具

| 工具 | 干什么 | 背后接口 |
|---|---|---|
| `ask` | 跟鲸倩说一句话，返回她原话（带记忆和工具；走**工作模式**） | `POST /api/chat`（entry=mcp） |
| `memory_search` | 搜记忆 | `GET /api/memory?query=` |
| `memory_remember` | 写一条记忆（可 pinned） | `POST /api/memory` |
| `stats` | 模型/今日调用/tokens/记忆条数 | `GET /api/stats` |

## 三、和窗口、QQ 的关系

```
             ┌─────────────┐
  DSH/Cherry │ 内置 MCP 适配 │──┐
  客户端      └─────────────┘  │
                              ├──▶ 本机服务（127.0.0.1:7889）──▶ 记忆/工具/模型
  普通用户    ┌─────────────┐  │
             │ 软件窗口      │──┘
             └─────────────┘
  QQ（可选）  ┌─────────────┐  │
             │ QQ 桥接       │──┘
             └─────────────┘
```

四个入口，一套服务、一份记忆、一份账本。模式各用各的：窗口=对话，QQ/MCP=工作（见 `docs/2.0-一核两前端.md`）。

## 四、注意

- 没有鉴权，只适合本机客户端，别把 7889 暴露到公网。
- 记忆是同一个库：适配器里记的事，软件版打开就能看到。
- 客户端超时设置要够（`ask` 可能走多步工具，默认 180 秒）。

## 五、怎么验

```cmd
node evals\mcp-test.js
```

这个用例真按 MCP 的 stdio 协议（一行一个 JSON-RPC）跟 `src/mcp/server.js` 聊一遍，
临时起服务 + 本地假模型，不碰真实记忆、不联网。覆盖：初始化、`tools/list` 四个工具、
记忆写入/搜回、`stats`、`ask` 真走 `/api/chat`、未知方法与未知工具不崩。

它和 `evals\mode-test.js` 都在 CI 里，每次推代码都会跑。
