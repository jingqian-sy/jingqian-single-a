# 内核合并（1A ↔ 3A）现状与回退办法

2026-11-03 起，「两个模板共用协议、不共用实现」这条设计决定改了一半：
**底层共用，编排各留各的**。原因很实际：两份实现各改一遍，成本太高，还容易改漏。

## 一、已经共用的

| 模块 | 谁用 | 说明 |
| --- | --- | --- |
| `util.js` | 1A + 3A | 读写 JSON、时间、分词、截断；3A 需要的 `readJsonl`/`sleep` 也并进来了 |
| `safety.js` | 1A + 3A | 四级红线 + 审计（3A 原来那份是它的子集） |
| `sandbox.js` | 1A + 3A | 沙盒三档（none/process/docker） |
| `router.js` | 1A + 3A | 选路、重试、失败冷却、按天账本、额度闸门 |

3A 现在的做法是一行转出去：

```js
module.exports = require('../src/xxx');
```

好处：以后红线和路由的改进只写一遍，3A 自动跟上。

## 二、故意没合的

| 模块 | 为什么不合 |
| --- | --- |
| `tools` | 3A 的角色用不到 remember/recall/fetch_url 这些；两边的 ctx 结构也不同（3A 没有 store/events）。硬合要先把 ctx 契约统一 |
| `memory` | 数据结构不同（3A 的 Memory 更简单，没有 tier/person/people），合并等于重写一份 |

将来要合，步骤是：先定一个最小 ctx 契约 → 给 3A 补 store 适配层 → 再换 tools → 最后统一 memory 存储格式。

## 三、验证

- `node evals/ci.js` 25 步全绿（含 3A 子集 m01 t02 t08 r01 与 3A 重启恢复）
- 合并后 3A 的评测分数没有掉：子集 4 题 × 2 遍全过

## 四、回退

三处提交，按需回退（保留中间态也行）：

```cmd
:: 只回退 router 共用（回到 3A 自己的 router）
git revert e8b72f8 --no-edit

:: 只回退 util/safety/sandbox 共用
git revert a6ad4b3 --no-edit
```

或者单文件恢复（更精准）：

```cmd
git checkout 441b4fc -- src-multi/router.js src-multi/safety.js src-multi/sandbox.js src-multi/util.js
```

回退后必须重跑：`node evals\ci.js`（3A 子集和重启恢复都在里面）。

## 五、给 2.0 的提醒

2.0（3A 正式版）直接 require 这四份共用模块，只写「角色怎么分工、谁审谁、怎么回炉」。
如果以后要动共用模块的接口，记得同步跑 1A + 3A 两边 CI，别只跑一边。
